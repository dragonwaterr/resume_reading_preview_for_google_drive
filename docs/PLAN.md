# 드라이브 PDF 이어보기 익스텐션 — 기획 · 결정 · 로드맵

> 최종 갱신: 2026-10-17
> 목적: 구글 드라이브 PDF 미리보기 진입 즉시, 지난번 마지막으로 보던 페이지로 자동 이동 (0단계 이어보기)
> 이 문서가 원본이다. 결정이 바뀌면 이 파일을 먼저 갱신한다.

---

## 1. 프로젝트 개요

### 문제 상황
- 구글 드라이브 PDF 미리보기는 항상 1페이지부터 열리며, 지난번에 어디까지 읽었는지 기억하지 않는다.
- 기존 책갈피 익스텐션(PDF Bookmarks for Google Drive)은 "미리보기 진입 → 책갈피 목록 열기 → 책갈피 클릭"의 수동 2단계가 필요하다.

### 목표
- 사용자의 추가 조작 없이, 미리보기 진입 즉시 마지막으로 보던 페이지로 이동시킨다.

### 범위
| 포함 | 제외 (Non-goals) |
|---|---|
| PDF별 마지막 페이지 자동 기록 | 여러 개의 책갈피 / 중요 페이지 표시 / 메모 |
| 미리보기 진입 시 자동 이동 | 드라이브 전체 PDF 목록·경로 파악 (Drive API, OAuth 미사용) |
| 이동 알림 토스트 + 끄기 옵션 | 책갈피 관리 UI (목록·편집·삭제) |
| | 드라이브 미리보기 외 PDF 뷰어 (Chrome 내장 뷰어, 다운로드 파일) |

## 2. 기능 요구사항

### FR-1. 마지막 페이지 기록
- 사용자가 페이지를 이동하면 해당 PDF의 현재 페이지를 저장한다.
- PDF 식별자는 파일명/경로가 아닌 드라이브 fileId를 사용한다. (이름 변경·이동에도 유지)
- 잦은 스크롤로 인한 과도한 저장을 막기 위해 일정 시간 멈췄을 때만 저장한다. (debounce)

### FR-2. 자동 이어보기
- 진입 시 먼저 저장소를 조회하고, 저장된 페이지가 있으면 해당 페이지로 자동 이동한다.
- 기록이 없는 PDF는 기본 동작(1페이지)을 유지한다.
- 페이지 기록(FR-1)은 조회·이동 분기가 끝난 뒤에 시작한다.
- 기록 시작 시점의 페이지는 저장하지 않으며, 사용자가 페이지를 이동했을 때만 저장한다.
- 페이지 로딩이 늦으면 일정 시간 대기 후 이동하며, 실패 시 조용히 포기한다.

### FR-3. 진입 경로 지원
- 드라이브 목록의 오버레이 미리보기와 새 탭 미리보기(`/file/d/{fileId}/view`) 모두에서 동작한다.

### FR-4. 미리보기 전환 처리
- 미리보기를 닫거나 다른 PDF로 전환하면 이전 PDF의 기록 로직을 정리하고, 새 PDF 기준으로 FR-2를 다시 수행한다.

### FR-5. 저장소
- 책갈피는 `chrome.storage.local`과 `chrome.storage.sync` 양쪽에 저장한다.
- 읽기: 두 저장소를 모두 조회하고 updatedAt이 더 최신인 값을 사용한다.
- 저장 형식: 키 `b:{fileId}` → 값 `{ p: 페이지, t: 마지막 기록 시각, o: 마지막 열람 시각 }` (제목 등 부가 정보 저장 안 함)
- 기록이 있는 PDF를 열면 열람 시각(o)만 갱신한다. (페이지 값은 변경하지 않음)
- sync 항목이 한도(설정 키 포함 512개)에 근접하면 열람 시각이 가장 오래된 책갈피부터 일괄 삭제한다. local은 삭제하지 않는다.

### FR-6. 이동 알림
- 자동 이동 성공 시 "N페이지로 이동했어요" 토스트를 짧게 표시한다. (기본값: 켜짐)
- 옵션 페이지에서 끌 수 있으며, 설정은 sync의 `settings` 키에 저장한다.
- 이동 실패 시에는 알림을 표시하지 않는다.

```js
// 저장 스키마 (sync / local 공통)
"b:1AbCdEf..." : { p: 47, t: 1760600000000, o: 1760650000000 }  // 책갈피
"settings"     : { toast: true }                                  // 설정 (sync 전용, 512개에 포함)
```

## 3. 비기능 요구사항
- 권한 최소화: `storage` 권한 + `https://drive.google.com/*` 호스트 권한만 사용한다.
- 데이터는 외부 서버로 전송하지 않으며, 브라우저 저장소(chrome.storage)에만 보관한다.
- 드라이브 DOM 변경에 대비해 DOM 선택자 의존 코드를 단일 모듈(driveDom)에 격리하고, 선택자 변경 시 빠르게 패치·배포할 수 있는 구조를 유지한다.
- 토스트 UI는 Shadow DOM으로 렌더링하여 드라이브 스타일과 격리한다.
- 문구는 `_locales`(en/ko)로 분리한다.

## 4. 결정 기록 (ADR)

### ADR-001. 1페이지 덮어쓰기 방지 방식
- 맥락: 진입 직후 뷰어는 1페이지를 표시하며, 기록 로직은 스크롤/IntersectionObserver 이벤트로 분기와 무관하게 비동기 실행된다.
- 선택지: (A) isRestoring 플래그 (B) 실행 순서 제어 — 분기 후 기록 시작 + 변경 시에만 저장
- 결정: B
- 근거: 상태 변수 없이 순서만으로 1페이지 덮어쓰기·이동 실패·레이아웃 밀림을 모두 방지. 단순함.

```js
async function onViewerOpen(fileId) {
  const saved = await loadPage(fileId);           // 조회
  if (saved) await jumpTo(saved, { timeoutMs: 5000 }); // 이동 (성공/실패 무관하게 진행)
  startTracking(fileId);                          // 분기 후 기록 시작
}
// startTracking: 시작 시점 페이지를 기준값으로만 쓰고, 값이 바뀔 때만 debounce 저장
```

### ADR-002. 페이지 감지·이동 방식 (루프 0 스파이크 결과)
- 선택지: (A) 뷰어의 "N / M" 페이지 표시 텍스트 (B) IntersectionObserver로 가장 많이 보이는 페이지 요소 판별 (C) 스크롤 비율 추정
- 결정: **B 변형 — 페이지 요소의 위치 기반** (오버레이 미리보기 기준, 2026-10-17 스파이크)
  - 뷰어: 보이는 `[role="dialog"]` 안의 보이는(레이아웃 박스가 있는) `[role="document"]`
  - 페이지: `[role="document"]`의 직속 자식 중 높이가 큰 요소 (`div.a-b-Xa-La`, 버튼 등 작은 자식 제외)
  - 스크롤 컨테이너: `[role="document"]`의 스크롤 가능한 가장 가까운 조상
  - 현재 페이지: 스크롤 영역 세로 1/3 지점을 덮는 페이지의 순번
  - 이동: `scroller.scrollTop += page.top - scroller.top`
- 근거:
  - 페이지 요소가 진입 시점부터 전부 존재한다 (이미지·"N/M페이지" 헤딩만 지연 생성) → 먼 페이지도 바로 이동 가능 (13p 문서에서 7·10페이지 이동 성공)
  - 계산한 페이지가 툴바의 페이지 번호 input 값과 스크롤 전 구간에서 일치했다
  - A(텍스트)는 로케일 의존("1/5페이지")이고 헤딩은 지연 생성되어 기각. 툴바 input(`aria-label="13페이지 중 10페이지"`)은 dialog 밖에 있어 보조 검증용으로만 본다
  - C(스크롤 비율)는 페이지 사이 간격·상단 버튼 높이 때문에 오차가 생겨 기각
- 관찰된 주의점:
  - 인접 파일 뷰어가 숨김 상태(display:none)로 미리 로드되어 있다 → 반드시 "보이는" 뷰어만 대상으로 한다
  - 같은 세션에서 다른 파일로 전환했다 돌아오면 드라이브가 파일별 스크롤 위치를 복원한다 → ADR-001의 "추적 시작 시점 페이지는 기준값으로만" 규칙과 충돌 없음
- fileId 출처:
  - 새 탭(`/file/d/{fileId}/view`): URL
  - 오버레이: URL은 폴더 URL 그대로이고 ←/→ 전환 시 그리드 선택(`aria-selected`)도 갱신되지 않는다. 대신 **툴바의 `[role="heading"]` 파일명과 일치하는 그리드 항목의 `data-id`**를 쓴다 (3개 파일 전환에서 실제 fileId와 모두 일치)
    - 바둑판 보기는 항목 `aria-label`("파일명 PDF 추가 정보…")로, 목록 보기(`tr[role="row"]`, aria-label 없음)는 텍스트가 파일명과 정확히 같은 하위 칸으로 매칭한다 (루프 4 다중 계정 테스트에서 발견)
  - 기각: `/drivesharing/clientmodel?id=` iframe(전환 순간에만 존재), 툴바 속성값(썸네일 id 잔존), 리소스 요청 URL(인접 파일 프리로드가 섞임 — 동명 파일 구분용 보조 후보로만 남김)
  - 매칭이 0개(그리드 가상화로 항목 미렌더링, 검색 화면 등)이거나 2개 이상(동명 파일)이면 fileId를 확정하지 않고 **추적하지 않는다** (R-01: 조용히 포기)
- 새 탭 미리보기: dialog 없이 같은 구조(`[role="document"]` + 직속 페이지 요소)이며 스크롤 컨테이너 클래스만 다르다(`ndfHFb-…`). 위 규칙 그대로 읽기·이동 성공 (13p 문서 7페이지)
- 오버레이 파일 전환(03→04→05→04) 중 300ms 간격 관찰에서 fileId·페이지 수가 섞인 과도 상태는 없었다. 그래도 진입 판정은 2회 연속 같은 값일 때만 한다
- 미검증(루프 4에서 확인): 100페이지 이상 문서, 다중 계정 경로(`/u/1/`)

### ADR-003. 저장소 구성
- 선택지: sync 단독 / local 단독 / 이중 저장
- 결정: local + sync 이중 저장, 읽기는 updatedAt 최신값 우선
- 근거: sync로 데스크톱 기기 간 이어보기, local로 sync 한도·쓰기 실패 대비. "sync 우선 읽기"는 sync 쓰기 실패 시 오래된 값을 읽으므로 기각.

### ADR-004. sync 한도 관리 방식
- 선택지: (A) 원형 큐 + 공유 포인터 (B) 항목별 타임스탬프 + 임계치 초과 시 일괄 삭제
- 결정: B
- 근거: 원형 큐는 FIFO라 "열람 오래된 순(LRU)"과 불일치, 공유 포인터는 여러 기기 동시 쓰기(키 단위 last-write-wins)에서 충돌, fileId 조회에 인덱스가 필요하나 항목당 8KB 제한 초과. B는 항목이 독립적이고 정리 비용도 512개 정렬 수준.

### ADR-005. Drive API 미사용
- 맥락: 전체 PDF 목록 파악에 필요한 `drive.metadata.readonly`는 restricted scope로, 공개 배포 시 검증 + 연례 보안 평가가 필요하다.
- 결정: Drive API/OAuth를 사용하지 않고, 미리보기 URL의 fileId를 키로 사용
- 근거: 핵심 가치(이어보기)에 전체 목록이 불필요하며, 공개 배포 장벽과 설정 비용 제거.

### ADR-006. 확장 업데이트 후 열려 있던 탭 처리
- 맥락: 확장이 재로드·자동 업데이트되면 이미 열린 드라이브 탭의 content script는 확장과 연결이 끊겨 chrome API가 모두 실패한다 (`Extension context invalidated`). 루프 3 테스트에서 확인.
- 선택지: (A) `scripting` 권한 + 업데이트 시 열린 탭에 재주입 (B) 연결 끊김 감지 시 조용히 중지, 탭 새로고침 시 정상화
- 결정: B (2026-10-17)
- 근거: 업데이트가 드물어 영향이 "업데이트 직후 이미 열려 있던 탭" 한정이고, 권한 추가(개인정보 탭 사유 작성)를 피한다. 업데이트가 잦아지면 A로 재검토.

### 기타 확정 사항
- [x] "마지막 페이지" = 마지막으로 머문 페이지 (가장 멀리 읽은 페이지 아님)
- [x] 이동 알림 = 토스트 기본 켜짐, 옵션에서 끄기
- [x] 오래된 기록 = local은 유지, sync만 한도 근접 시 정리

- 병합·삭제 같은 순수 로직은 함수로 분리해 단위 테스트한다.

### 9-4. 범위 밖 제약 (수용)
- 모바일 Chrome(Android/iOS)은 익스텐션을 지원하지 않음 → sync 이점은 데스크톱 Chrome 간 동기화에 한정
- 다운로드 후 Chrome 내장 PDF 뷰어로 연 PDF에는 익스텐션 개입 불가
- 같은 PDF를 여러 탭·기기에서 동시에 읽는 경우 마지막 기록이 우선함 (last-write-wins 수용)
- 확장 업데이트 직후 이미 열려 있던 드라이브 탭은 새로고침 전까지 이어보기가 동작하지 않음 (ADR-006)
